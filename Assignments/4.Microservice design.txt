Problem Statement
You are given monolithic application:
Online Food Delivery App
Features:
•	User Login 
•	Restaurant Listing 
•	Search 
•	Cart 
•	Order 
•	Payment 
•	Delivery Tracking 
•	Notifications 
•	Ratings & Reviews 


1.	Individual services 


- User Service : To handle user login(Need to use JWT authentication)
- Restaurant Service : To collaborate with different restaurants and to deal with the food menu
- Payment service : To handle payment processing
- Delivery Service : TO handle food delivery associates and to track delivery
- Notification Service : TO handle notifications
- Review Service - TO write reviews and ratings
- Order Service : TO handle food orders
- Search service : To handle food and restaurant search


2.	Database per service 
 
User Service  : User details DB (to store user specific info)
Restaurant Service :Restaurant DB to store restaurant details and food menu details
Payment service : To handle payment processing
Delivery Service : TO handle food delivery associates and to track delivery
Notification Service : No DB needed, some message publishing can be used.
Review Service - TO write reviews and ratings
Order Service : TO handle food orders

3. API Communication

 Synchronous 

API Gateway -> All Services
Order -> Payment
Order -> Delivery

Asynchronous (Event-based via Kafka)

Order -> Payment
Payment -> Notification
Order -> Delivery
Review -> Notification

 4. Kafka Usage (Event-Driven Services)

Order Created :: Order -> Payment, Delivery
Payment Completed :: Payment -> Notification, Order
Order Status Update :: Order -> Notification
Delivery Updates :: Delivery -> Notification
Review Added :: Review -> Notification


5. High Scaling Services

 Search Service
Notification Service
Order Service

6.	Which service is business critical 
Order Service

7.	Failure handling strategy 
Timeouts 
Circuit Breaker (Resilience4j) -> to prevent cascading failures in microservice
